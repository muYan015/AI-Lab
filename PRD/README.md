# AI NPC 可交互世界

一个世界观完整、NPC 有且只有一个「自己」的可交互软件。对话是第一入口：你可以和角色私聊、群聊、送礼、建立关系，也可以坐在酒馆里看他们过自己的日子。想创作时，可以自己建世界和人物，发布到广场，或把别人的世界、单个角色拼成新世界。

当前目录是 **产品需求文档 v2.0**（总表 + T01–T20）。它规定软件要做什么、怎么验收，不包含可运行源码，也没有视觉规范。

## 它和普通聊天机器人的差别

真实感在这里不是「回复更长」，而是四件可以验收的事：

- **连续性**：换会话还是同一个人。记忆、日程、关系不会因为新开一个聊天窗口而重置。
- **因果性**：送礼、承诺、拒绝会改记忆、目标、日程和关系，并且之后能被合法引用。
- **认知一致性**：角色只知道自己看到、听到或合法获知的事。听不清的内容不会被当成原文下发。
- **自主性**：行为来自目标、性格和日程，而不是围着玩家反复闲聊。

亲密关系需要适龄和双方意愿。自定义提示词、世界包、角色包都不能覆盖安全和公序良俗边界。

## 谁在用

| 角色 | 主要在做什么 |
| --- | --- |
| 体验型玩家 | 打开就能聊。不需要先建世界。 |
| 长期互动玩家 | 跨会话延续关系，追承诺和线索。 |
| 世界创作者 | 写世界观、人物和初始关系，规则要真正约束角色。 |
| 混搭创作者 | 下载别人的整世界或单个角色，冲突可见、确认后才合并。 |
| 发布者 | 管草稿、审核、版本和下架。私人聊天不会被打进作品包。 |
| 运营与审核（内部） | 审内容、处理举报、看成本和任务是否真实完成。 |

## 怎么用

软件按三个一级入口组织：**对话**、**世界**、**我的**。本人作品的主入口在「我的」。高频任务（最近会话、当前世界、常用创作）可以直达，不必逐层点进去。

### 直接开始玩

1. 从会话列表进入最近的私聊、群聊或酒馆。
2. 创建或进入一个世界时，选择身份：以外来**旅人**进入，或填写一个**世界内身份**。两种身份都要填档案，并会影响开场和 NPC 对你的认知。换一个世界的身份，不会改掉其他世界里的你。
3. 在对话里完成行动：送礼、邀请、承诺、离开。这些行动挂在会话里，不另开一套互不相干的存档。
4. 事件确认之后，记忆、目标和关系发生变化。下一次对话或生活分享里，角色可以引用这件事。
5. 离开再回来时，世界按现实时间 1:1 继续走。进入具体世界会看到一份简报：公开大事、你能够知道的变化、NPC 的联系。简报不是全知视角。

模型还没配好时，可以编辑世界和人物、看记录，或用演示 / 规则级推进。引导的最后一步才指向 API 配置。演示内容和真实生成必须能区分开。

### 创作并发布

1. 新建或编辑世界：名称、题材、背景、开局钩子，以及七类设定（起源与力量、地理、种族、势力、生物、年表、重要角色）。
2. 设计 NPC：身份、外观、背景、性格、目标、说话方式、初始关系。
3. 设定规则的作用范围：全局、单个 NPC，或一次选中多个 NPC。
4. 校验、选择许可、打包。发布预览里不能出现私人聊天、玩家偏好或模型密钥。
5. 他人可以下载整包世界，也可以只下载其中一个角色。组合两个来源时先列出冲突，确认后生成派生世界，原作保持不变。

可共享的是**世界定义**；你正在玩的那一局是**私密运行存档**。改模板不会自动覆盖进行中的剧情，云端作品更新也不会强行升级读者正在游玩的存档。

## 功能一览

### 对话、群聊与酒馆

- 私聊、自己建的群聊、带场景和在场条件的酒馆。
- NPC 可以主动找你，也可以和其他 NPC 聊天，不要求每句话都由玩家点名。
- 酒馆里的交谈和走动来自世界规则、目标、关系和日程。玩家可以加入，也可以只观察。
- 流式回复、停止、编辑、删除、末条重生成、点名、在场人员、时段切换。
- 忙碌、缺席、正在生成、等待回应、请求失败是不同状态。「暂无回应」不等于系统坏了。系统错误走统一弹窗，不能伪装成角色拒绝说话。
- 同一个 NPC 正在和你私聊时，不会同时在另一个实时群聊里继续发言。新会话用的仍是这一个 NPC 的状态。

### 礼物

支持玩家送给 NPC、NPC 送给玩家、NPC 之间互送。点击「赠送」只是表达意图。送达、接受、拒绝、取消是分开的状态，**确认之后才结算**。同一件礼物，不同性格的角色可以给出不同评价。失败重试不会重复赠送、重复扣减或重复改变关系。

### 关系

关系是双向的，而且可以不对称：A 信任 B，不等于 B 信任 A。好感、信任、熟悉度分开看；对人的关系、对行为的喜好、短期情绪和稳定关系类型也不混成一个分数。高好感可能发展出恋爱等亲密剧情，但高分不等于自动同意。角色可以拒绝或结束关系，结束后共同历史仍然保留，普通互动可以继续。

界面呈现关系的方式是描述，不是刷分用的硬性数值。

### 生活动态

NPC 的分享来自自己的日程、经历、兴趣和关系，不围着玩家编故事。发不发、发给谁、稍后发还是不发，由角色自己决定。动态必须对应真实发生过的事，或角色已知的来源。聚合页和这个人的单人页使用同一份数据；你不在受众里就看不到。读到一条动态，本身会让读者获得相应的知识，但不是事件全貌。

### 记录与纪事

玩家可以写日志、做手动记录、回看聊天摘要。世界纪事按事件列出参与者、时间、地点、结果和后续。关系变化要能看到「为什么变了」。承诺和线索可以回到原来的会话。普通记录不暴露 NPC 的隐藏认知；记忆、调度原因和实际提示词只在高级检视里。不同世界的经历不会被拼成同一条事实。

### 旅人身份与偏好

跨世界的玩家资料和「这一局里你扮演的身份」是分开的。创建时可以复制资料，之后的修改不自动共享。只有当前身份里允许 NPC 知道的字段会进入对话。

偏好总结类似一种自我了解（不必照搬 MBTI 的分类）。推断要带来源场景、证据和置信度，可以更正，也可以关闭自动分析。你在某个世界里扮演冷漠角色，不会因此被记成现实中缺乏同理心。NPC 默认读不到你的全局画像。

### 规则与提示词

可以写全局底层规则和写作偏好，也可以只作用于一个或一组 NPC。每条规则有名称、范围、目标、启停和版本。冲突时要能看到两条规则各自的来源，以及实际采用了哪一种。安全边界不能被用户、世界包、角色包或临时消息覆盖。导入的角色提示词不能读取密钥，也不能执行本地命令。

### 感知与酒馆小窗

谁能察觉什么，由视觉半径、听觉半径、遮挡、音量、噪声和注意力共同决定。玩家可以调节这些数值；人设里没写时使用均衡值。首版假设（待内测校准，不是实测结论）：普通视觉约 8 米、听觉约 6 米。

酒馆里有一个可折叠的俯视小窗，只画出你能够感知到的移动和交流。正文同样按这个范围筛选。听得见声音但听不清词句时，界面给线索，不给原文。

移动不依赖小窗是否展开：展开时可以点选落点，收起时可以用指令或「走近某人」。两个入口写的是同一个移动意图，由日程中枢按「唯一身体」裁决。此条仍待最终确认（见 T19 `UNR-E04`）。

### 账号、存档与时间

- 邮箱与密码登录，可验证、重置；头像和名字可改。
- 资产分层：账号资产、本局状态、系统数据、秘密、公开作品。
- 存档、自动保存、恢复。恢复不会把已经送出的礼物再复制一份。
- 世界时间与现实时间 1:1。离线期间世界继续变化，不再默认冻结。
- 表情资源属于账号；局内表情消息和 NPC 是否理解其含义是另一件事。收藏不跨局灌进 NPC 记忆。

### 社区广场

作品带预览、类型、标签、作者、版本、依赖和授权。发布者管理草稿、提交、审核、版本和下架；读者可以举报。已下载的内容在社区暂时不可用时仍可本地使用。内容包按数据导入：校验格式、字段和大小，不执行包内脚本，不读取 API Key。

## 世界怎么运转

### 四个中枢

记忆、决策、日程、好感是四个共享的运行系统，不是贴在提示词末尾的背景文字。

| 中枢 | 做什么 |
| --- | --- |
| 记忆 | 按 NPC 单独形成、分类和召回。浅层是近期对话和现场信息，深层是重要经历、承诺和长期关系。遗忘先降低召回权重，不把世界事实和有效承诺直接删掉。 |
| 决策 | 性格、需求、目标和价值观变成选择权重。先去掉不合法、不可行的行为，再比较收益、关系、风险、成本和重复度。没有合理行动时可以不行动。 |
| 日程 | 每个 NPC 在一个运行世界里只有一个当前主体。默认习惯、临时安排、承诺和当前活动分开。冲突时拒绝、改约或明确打断，不能靠把界面藏起来假装互斥。停止生成或关掉页面不等于角色离场。 |
| 好感 | 玩家对行为的偏好，和 NPC 对行为的评价，是两套东西。评价只依据这个角色观察到或获知的事件，重复事件不重复结算。 |

### 五层知识

一条信息在下发给模型之前，要经过五层过滤：

1. 事件事实
2. 谁可以感知
3. 谁实际获知
4. 相信程度
5. 记忆是否还能被召回

转述是声称，不是事实。不可辨的台词不下发。不在场的人不会立刻知道私密内容。

### 一次互动的顺序

收到输入或日程触发 → 校验是否可行、是否越界 → 确定谁在场、谁知情 → 生成候选动作 → 去掉时间和地点冲突后按权重选择 → 执行前再确认没有被占用 → **由系统确认状态变更**（模型不能直接改世界状态）→ 按知情范围写入记忆、关系依据和日程，每件事只结算一次 → 生成与结果一致的呈现，并留下下一步。

玩家的对话优先，但不能压过合法性、意愿和感知。

### 两个大循环

**世界体验**：选择或创建世界 → 配置身份 → 进入对话或酒馆 → 玩家与 NPC、NPC 与 NPC 互动 → 事件产生后果 → 记忆、目标、日程、关系改变 → 后续行为或分享被看见 → 玩家获得新线索 → 再次互动。

**创作者生态**：创作 → 校验、选许可、打包 → 上传 → 他人预览下载 → 解决冲突后组合成新世界 → 运行并反馈 → 改进原作或依法发布派生。

## 技术形态

分阶段建设，不在第一阶段同时做账号、审核和社区。

| 维度 | 当前结论 |
| --- | --- |
| 应用形态 | 先做本地可玩，再加模块化云后台。后台分别管账号、存档、作品、运行和分析，不是所有人共享同一个世界。 |
| 时间 | 现实 1:1。离线推进需要独立的调度和模型预算；额度用尽时降级为规则级推进，并明确告诉用户，不能假装任务已完成。 |
| 模型 | 玩家自备 API（BYOK），支持多个服务商。无密钥的本地路径（如 Ollama）不能被「缺少 Key」的全局提示拦住。 |
| 知识下发 | 五层过滤之后才进入提示词。 |
| 通信 | 先按现场交谈和世界设定里写明的合法渠道。世界内远程通信必须由该世界显式支持。此条待拍板。 |
| 多端同步 | 本期不做。若以后做，同一世界不能多端同时乱写，也不能因此复制出 NPC 分身。 |

本地存储不等于内容从不离开这台设备。软件必须说明哪些上下文会发到哪个模型地址。密钥遮蔽，日志脱敏，作品包和备份排除秘密。

任务用世界实例、NPC 实例、会话和任务编号一起隔离。切换世界、停止生成或写入失败时，结果不能串到另一个局，已确认的事件不能再结算一次。保存失败要看得见，不能把「内存里改过了」显示成「已经保存」。

## 版本路线

| 阶段 | 目标 | 做完的标志 |
| --- | --- | --- |
| 一、本地可玩闭环 | 一个人能从头玩到「有后果」 | 一次互动改变了状态，并且之后被引用；没有重复结算，没有不该知道的泄漏 |
| 二、账号与存档 | 身份和资产稳定 | 登录、存档、恢复、统一错误提示可用；恢复不复制已送礼物 |
| 三、社区与离线 | 内容可复用，时间连续 | 下载和混搭可用；离线简报只含可知信息；成本可控 |
| 四、运营与优化 | 按数据决定投入 | 指标可采集、可查看；北极星指标拍板并设门槛 |

对话、世界、NPC、四中枢、身份、规则，以及对应版本的性能与安全，是发布门槛。物理互斥被破坏、数据泄漏、未成年性化内容、重复结算、秘密泄漏、存档失败不可见、系统错误伪装成角色行为，任一出现都不得发布。

本期不做：云同步与多端同时写入、真实付费和虚拟经济、语音合成、评论生态、榜单推荐，以及任何配色、字体、动效规范。

## 安全与合规

- 禁止未成年人性化或剥削内容。年龄不明时不进入成人内容路径。
- 礼物、高好感、付费或连续登录都不能换成强制亲密。角色可以拒绝、冷却、结束关系。
- 私人聊天、礼物关系史、NPC 私密记忆和真人画像默认不上传广场。分享前要看到范围并确认。
- 广场只审核已提交发布的内容。纯本地内容由客户端规则拦截，并说明「本地内容不在审核范围内」。
- 玩家画像默认只有本人可见，不是心理诊断。可以查看、纠正、删除和停止采样。
- NPC 和动态要标明是 AI / 模拟世界内容，不冒充真人，不用内疚、威胁或失联惩罚逼用户留下来。
- 分析只记录完成或失败、耗时、端类型、内容类型和去标识统计。默认不上传聊天原文、人物秘密、玩家画像或 API Key。引导流程和 NPC 自动行为不计入功能使用次数。

## 还没拍板的事

T19 里有 37 项。建议先定这五件，它们会挡住会话模型、成本和存档设计：

1. **通信媒介**（`UNR-A01`）：私聊和群聊在世界里靠现场、书信，还是远程通信。
2. **离线在哪里算**（`UNR-A04`）：本地补算，还是云端调度，以及模型授权和费用。
3. **动作确认时序**（`UNR-C01`）：角色说「收下了」之前，事实必须已经结算成功。
4. **本地与云的边界**（`UNR-G01`）：每一期到底新增哪些服务。
5. **历史回滚**（`UNR-F01`）：已执行的行为不自动退回；是否另外提供完整回滚。

状态用语：文档里的「明确 / 已确认」表示已经拍板；「基线」来自原产品手册；「建议」是待确认的提案；「待定」只在 T19。

## 成功看起来像什么

北极星指标尚未正式拍板。当前候选是：每周完成「有后果、并且之后被用到」的互动闭环的独立玩家数。同一玩家每周只计一次。模型自己聊起来的字数、反复重试，都不算。

同时看这些反向信号：单次闭环的 Token 和调用次数、等待时长、无意义自聊、秘密泄漏、重复结算、误拦截、存档失败。关键安全和一致性缺陷不能用平均分掩盖。
