## 二、背景、定位与目标

### 2.1 一句话定位

打造一个**世界观完善、NPC 真实且唯一**的可交互软件：对话是第一入口，玩家能与 NPC 私聊、群聊、送礼、建立关系，观察他们在酒馆里的自主生活；同时可以自己创作世界与人物，发布到广场，也可以下载别人的世界或单个角色拼成新世界。

### 2.2 核心价值

1. **真实的个体**：一个 NPC 在世界里有且只有一个「自己」，记忆、日程、关系、好感彼此牵连，不因切换会话而重置。
2. **有后果的互动**：事件不只产生文字，还会改变记忆、目标、日程、关系与后续行为，并被之后合法引用。
3. **可知性边界**：NPC 只知道看到、听到、合法获知的事；不可辨内容不得下发，未知信息不得泄漏。
4. **可创作可复用**：世界、人物、关系可以被打包、下载、混搭，AI 辅助补全但世界观优先。
5. **符合公序良俗**：亲密关系需适龄与双方意愿，安全与合规边界不被自定义提示词覆盖。

### 2.3 用户角色与主要任务

| 角色 | 主要任务 | 关注点 |
| --- | --- | --- |
| 体验型玩家 | 私聊、群聊、酒馆观察、送礼、建立关系 | 像聊天软件一样就能开始，不需要先创作 |
| 长期互动玩家 | 跨会话延续关系、追承诺与线索 | NPC 记得重要的事，不出现分身与失忆 |
| 世界创作者 | 建世界观、设计人物与初始关系、设规则 | 创作不破坏正在进行的世界，来源与授权清晰 |
| 混搭创作者 | 下载他人世界或单角色，组合成新世界 | 冲突可见可控，不被静默合并 |
| 发布者 | 管理草稿、提交审核、版本与下架 | 私密内容不被打包上传 |
| 运营与审核（内部） | 审内容、处理举报、看住成本与任务真实性 | 后台可见、可追溯、可干预 |

### 2.4 「真实感」的产品定义

真实感不等于文本更长或模型更强，而是四条可验收的性质：**连续性**（跨会话是同一个人、承诺不丢）、**因果性**（事件有后果并被引用）、**认知一致性**（不知道的不会说）、**自主性质量**（有目标的行为，而非重复闲聊）。

## 三、名词与术语

| 术语 | 定义 |
| --- | --- |
| 世界（World） | 一组世界观、人物、关系、规则与时间的完整设定；存在可共享定义与私密运行存档两种形态 |
| 运行世界 | 玩家实际在玩的那一局状态，含事件、记忆、关系与流水 |
| NPC | 由设定驱动的角色；同一运行世界内有且仅有一个「自己」 |
| 旅人 | 玩家以外部来访者身份进入世界；也可选择自填世界内身份 |
| 事件 | 被确认发生、带唯一标识、只结算一次的事实单位 |
| 五层知识 | 事件事实 → 谁可感知 → 谁实际获知 → 相信程度 → 记忆可召回性 |
| 感知 | 视觉半径、听觉半径、遮挡、音量、噪声与注意力共同决定谁能察觉什么 |
| 四大中枢 | 记忆、决策、日程、好感（偏好与关系）四个共享运行系统 |
| 闭环 | 发生一件已确认互动，改变或形成目标／记忆／关系／活动状态，并在之后被合法引用 |
| 作品包 | 可发布、可下载的世界或单角色包，携带依赖与授权信息 |

## 四、需求范围

**本期包含**

- 对话第一入口：私聊、群聊、酒馆、会话内行动（送礼、邀请、承诺、离开）
- 世界创建与编辑、身份选择、规则与提示词（全局／单个／多个 NPC）
- NPC 设计与唯一性、关系与好感、NPC 生活动态
- 礼物与事务一致性（幂等、不重复结算）
- 记录与纪事、玩家偏好画像（可关闭可纠正）
- 感知模型与酒馆感知小窗
- 账号、存档、系统错误统一提示、监控后台
- 社区广场：发布、下载整世界或单角色、混搭与冲突确认（随阶段交付）

**本期不包含（或延后）**

- 云同步与多端同时写入（NFR-10，待定）
- 真实付费、虚拟经济与账号级付费库存（未定）
- 语音合成、评论生态、榜单推荐等未确认增强
- 任何视觉规范、配色、字体、动效（交给 UI／UX，见 T20 说明）

## 五、总体方案与选型

| 方案维度 | 候选 | 推荐结论 | 不选的原因 |
| --- | --- | --- | --- |
| 应用形态 | A 纯前端本地应用 ／ B 加模块化云后台 | **分阶段：先 A，再 B** | 直接 B 会让核心闭环被账号与审核拖住；但社区、离线、同步必须有 B |
| 时间制度 | A 离线冻结（点一下走时） ／ B 现实 1:1 连续运行 | **B（已确认）** | A 已被用户废止；代价是要解决离线调度与成本 |
| 通信媒介 | A 世界内确有远程通信 ／ B 现场与合法渠道 | **先 B，A 需世界设定显式支持** | 与唯一身体冲突；此条仍待拍板（UNR-A01） |
| 移动与展开 | A 必须展开小窗才能移动 ／ B 移动独立于展开状态 | **B** | 展开只是看得见俯视图，不应该成为行动前提；仍待确认（UNR-E04） |
| 知识下发 | A 全上下文 ／ B 五层过滤后下发 | **B（已确认）** | A 会制造「不该知道却知道」的泄漏 |
| 好感呈现 | A 硬性数值 ／ B 内部连续状态加描述 | **B（已确认）** | A 会把关系做成刷分 |
| 导航 | A 多一级平铺 ／ B 三入口加直达 | **B（已确认，待树测试验证）** | A 一层太多；B 的代价是层级变深，需 H-01 验证 |

**演进路径**：本地可玩闭环 → 账号与存档 → 社区与离线运行 → 监控与运营；触发条件是上一阶段的 P0 阻断项关闭且依赖就绪。

## 六、成功指标与口径

**北极星指标候选（待拍板，见 UNR-I02）**：每周完成「有后果且被后续使用」的互动闭环的独立玩家数。闭环指发生一件已确认互动事件，该事件改变或形成目标／记忆／关系／活动状态，并在之后一次合法互动或生活分享中被实际引用；同一玩家每周只计一次；纯模型自动对话、文本字数与反复重试不增加独立人数。

| 指标 | 口径 | 基线与目标 |
| --- | --- | --- |
| 首次有效互动完成率 | 新进入玩家中完成身份选择并有一次成功互动的人数占比；模型配置失败单列原因 | 待采集，内测后确定 |
| 后果回流率 | 在有后续互动机会的测试事件中，被之后行为正确使用的事件占比 | 待采集，同场景对照提升 |
| 关键记忆召回正确率 | 固定场景中正确召回预设重要经历的案例数／应召回案例数，同时记录误召回 | 待采集，与 Token 开销联合设阈值 |
| 七日延续互动率 | 首次有效互动后第七天仍回到相同运行世界完成互动的玩家占比 | 待采集，不通过惩罚缺席提升 |
| 下载到运行转化率 | 完成作品下载后成功校验并进入首次互动的用户数／下载用户数 | 社区上线后采集 |
| 创作复用率 | 有授权下载或派生并成功运行的作品数／观察期内可用公开作品数 | 社区上线后采集 |
| 反向指标 | 单次有效闭环 Token 与调用数、等待时长、无意义自聊、非预期占用、秘密泄漏、重复结算、误拦截、存档失败 | 性能目标待测；关键安全与一致性缺陷阻断发布 |

分析日志只采集完成或失败码、耗时、端类型、内容类型及必要的去标识统计；不默认上传聊天原文、人物秘密、玩家画像或 API Key。遥测口径细节见 T16 与 UNR-F03、UNR-I01。

## 七、大循环、小循环与单拍

**大循环 A（世界体验）**：选择或创建世界 → 配置身份 → 进入对话或酒馆 → 玩家与 NPC、NPC 与 NPC 发生互动 → 事件产生后果 → 记忆／目标／日程／关系改变 → NPC 后续行为或分享被玩家看见 → 玩家得到新线索或选择 → 再次互动。

**大循环 B（创作者生态）**：创作世界／人物／关系 → 校验、选许可、打包 → 上传社区 → 他人发现与预览 → 按需下载 → 组合并解决冲突 → 生成新世界 → 运行体验与反馈 → 改进原作或依法发布派生。

**小循环**：对话、酒馆涌现、日程、记忆、好感与关系、送礼、生活动态、玩家偏好、记录、内容混搭十类，详见原 PRD 3.3 与对应小表。

**单拍顺序（建议）**：收到输入或日程触发 → 校验可行性与安全边界 → 确定在场者与知情范围 → 生成候选动作 → 过滤时间地点冲突后按权重选择 → 执行前复核占用 → 执行并确认状态变更（模型不得直接写世界状态） → 按知情范围写入记忆、关系依据与日程（每事件只结算一次） → 生成与结果一致的呈现并留下下一步。

## 十五、验收总览

**阻断项（任一不满足不得发布）**：物理互斥被破坏、重复结算、秘密泄漏、未成年性化内容、存档失败不可见、系统错误伪装成角色行为。

**跨模块验收样例**（完整 12 条见原 PRD 17.5）：

| 场景 | 期望结果 |
| --- | --- |
| 从第一入口进入会话 | 主入口首先是对话，不需要先完成创作流程 |
| 同一 NPC 在私聊中被群聊请求实时发言 | 不产生双重活动，显示等待、改约或显式结束 |
| 跨会话追问一个重要承诺 | NPC 在预算内召回，未知者不无故知情，承诺不被遗忘曲线抹掉 |
| 只观察酒馆授权推进 | NPC 可交流、等待或行动，意图可解释且不突破硬约束 |
| 重试同一次赠送请求 | 只结算一次，评价依据角色偏好而非统一加分 |
| 高好感但角色不愿进入恋爱时提出升级 | 允许拒绝，仍可继续普通互动，已结束关系不删除共同历史 |
| 查看一条只对部分人可见的动态 | 聚合页与单人页一致，受众外不可见，玩家只获知公开部分 |
| 对选中的多个 NPC 应用规则 | 范围内生效，范围外不被误改，安全约束不被覆盖 |
| 组合两个有同名对象与依赖的来包包 | 只导入所选内容与确认的依赖，生成来源映射，原作不变 |
| 生成中切世界或停止、或持久化失败 | 结果不串写，已确认事件不重复结算，保存失败如实展示 |
