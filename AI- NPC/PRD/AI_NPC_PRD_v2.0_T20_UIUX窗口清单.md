# T20 UI／UX 窗口清单（交给 UI／UX 发挥的底稿）

> **本表只回答一个问题：什么东西需要一个界面／窗口来承载。**
> **本表不做任何审美要求**：不规定配色、字体、字号、字重、圆角、阴影、图标风格、插画风格、动效、间距节奏、品牌调性，也不规定具体像素尺寸。
> 表中「承载形态」一列只是**交互结构建议**（全屏页面、弹层、抽屉、内嵌面板、浮层、小窗），UI／UX 可自行改为更合适的结构，只要任务能完成、状态能看清。
> 「端差异」一列只写**职责分工**，不写视觉表现；两端可以长得很不一样，但同一任务两端都要能完成。
> 每条都给了关联需求编号，界面设计以需求为准；需求本身还没定的，以 T19 的状态为准，界面先不要做死。

## 十二、所有界面都要满足的通用要求

> 这一节不是审美要求，是**可用性底线**。做 UI／UX 的人可以任意发挥视觉，但这些不能少。

| 编号 | 通用要求 | 验收口径 |
| --- | --- | --- |
| UIX-G01 | 四种状态齐全：空、加载中、错误、边界（超长文本、超多数据、极小屏） | 每个界面都能指出这四种状态各自长什么样 |
| UIX-G02 | 每次操作都有反馈：成功、失败、进行中 | 点击后 1 秒内出现可感知反馈，失败给出原因与下一步 |
| UIX-G03 | 危险操作二次确认，重要操作可撤销或可恢复 | 删除、覆盖、发布、撤销授权必须有确认步骤 |
| UIX-G04 | 键盘可达、焦点可见、读屏可朗读、对比度满足基本可读性、可减少动效 | 仅键盘可完成核心任务；关键控件有可朗读标签 |
| UIX-G05 | 同一操作在不同界面保持同一语义与同一说法 | 例如「删除」不在这里叫删除、那里叫移除却行为不同 |
| UIX-G06 | 系统问题与角色行为必须能区分 | 系统错误走统一弹窗；NPC 拒绝是局内行为，不能伪装成系统故障 |
| UIX-G07 | 同一任务在手机与桌面都能完成 | 两端布局可不同，任务完成率都要达标 |
| UIX-G08 | 不呈现界面承载不了的信息 | 感知范围外、不可辨内容、未授权信息不得出现在任何界面上 |

## 十三、本表与其他表的关系

- 本表是**界面承载清单**，不是视觉方案；视觉、配色、字体、动效一律交给 UI／UX。
- 每条都关联到 T01–T18 的具体需求；需求状态为「待定」的，界面先按可调整的方式设计，不要做死。
- 未决项（T19）直接影响部分界面是否存在，例如 UIX-66 取决于 UNR-F01，UIX-57 与 UNR-D01 相关。
- 非功能与无障碍指标见 T17、T18；本表第十二节只是底线，不是全部要求。
