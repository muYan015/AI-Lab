1 · 设计原则

五条原则按优先级排序，冲突时以序号靠前的为准。它们把 PRD 里"可验收的真实感"翻译成界面约束。

P1 不撒谎

界面呈现的必须与世界真实发生的一致：不可辨内容只给线索；系统故障绝不伪装成角色不理人；未保存不显示"已保存"。

P2 状态可辨

每件"还在路上"的事都有独立可区分的样子：意图／执行中／已确认／被拒绝／失败五态分离。

P3 边界可见

谁能知道什么要能被感知：感知范围用虚线表达，受众外内容根本不渲染（灰掉也算泄漏）。

P4 内容优先

视觉退到文字后面：单色系 + 一个强调色，无渐变炫技，动效只服务状态变化。

P5 同一套说法

同一动作在所有界面同一名称、同一结果。「删除」不在这里叫删除、那里叫移除；拒绝与失败不混用颜色。

反面清单 · 设计评审逐条查
给关系加数值条 用红色表达"角色拒绝" 系统报错写成角色台词 加载动画掩盖"其实没在动" 灰色预告感知外的信息 为填满版面生成占位剧情

2 · 设计令牌

「纸与墨」：界面 90% 无彩——暖纸白底 + 墨黑文字与控件；唯一的彩色留给主行动按钮与语义状态。层级靠底色深浅建立，不靠投影堆叠。

2.2 唯一强调色与语义色

行动色取石青：色相 199°（往青偏，是矿物颜料的方向，不是屏幕蓝），饱和 47%——比浏览器默认蓝低一半。低饱和是「舒服」的来源，高对比是「醒目」的来源，两者不冲突。

4 · 状态语义系统

六套语义系统是本规范最重要的部分，是 PRD 中"可验收的真实感"在界面上的唯一落点。

4.1 事务三段式（送礼 / 邀请 / 承诺 / 移动）

意图 → 待确认 → 执行中 → 已确认 / 被拒绝 / 失败
状态Chip颜色界面行为
意图已表达待确认中性虚线显示确认卡：送什么、给谁、可取消。不扣减、不结算
执行中处理中墨青禁用重复提交；关闭页面不中断，可回来查看结果
已确认已确认成功绿写入流水与纪事，可被后续引用
被拒绝被拒绝中性灰说明谁拒绝、为什么；可换个方式再来
失败未完成危险红走系统错误家族；明确"没有送出、没有扣减"

幂等可见：同一事件的重试显示"你已在 3 分钟前送出，正在确认结果"，不出现第二个赠送入口。

4.2 角色状态 vs 系统状态

角色侧 · 中性灰
老陈这会儿在忙，没搭话。在忙
可以去找 阿禾，也可以稍后再来

叙述体、带角色主语；必须给可替代下一步。

系统侧 · 统一弹窗
请求失败
模型服务未返回，本次内容没有生成，也没有改动任何状态。
ERR-MODEL-429

任何系统故障不得写成角色台词；反之角色拒绝不得弹系统弹窗。

13 · 文案规范与无障碍

同一操作同一说法；仅键盘可完成核心任务；对比度全部达到 AA。

用语词典
用这个不用这个原因
删除移除、清除同一动作同一说法
撤销回退、反悔撤销 = 未提交的操作
恢复（存档）回滚、还原回滚语义更强
已确认成功、搞定事务语义
被拒绝失败（红）拒绝是角色侧，中性
在忙 / 缺席离线、隐身角色没有在线状态
听不清未知内容用户能懂
句式规则
1. 主语明确：「老陈没有回应」vs「请求失败（ERR-…）」，绝不模糊成"操作未完成"。
2. 给下一步：每条错误 / 空态 / 拒绝后必须有一个可点击的行动。
3. 不拟人化系统：系统提示不用第一人称，不用"哎呀"。
4. 不承诺未发生：未保存前不写"已保存"。
5. 时间：会话内用相对时间；纪事用绝对时间 + 世界内时间。
无障碍检查项（WCAG 2.1 AA）
项要求
对比度正文 ≥ 4.5:1，大字 ≥ 3:1，图形边界 ≥ 3:1 全部达标
焦点可见2px 墨青环 + 2px 偏移，禁止 outline:none
键盘登录、进入会话、送礼、确认、保存、提交作品均可仅键盘完成；Esc 关闭弹层并回焦
读屏图标按钮有标签；状态 Chip 文字可朗读；关系图有文本替代；生成中 aria-live
触控可点区 ≥ 44×44，相邻 ≥ 8px；移动输入区不被软键盘遮挡
动效遵守 prefers-reduced-motion；无闪烁
缩放200% 文本不破版；无横向滚动（表格除外）
表单错误用 aria-describedby 关联；必填写"必填"而非仅星号
